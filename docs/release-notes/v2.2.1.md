# AMPM Viewer 2.2.1

Imports from the parts CSV and the samples template land on the right parts
when the two number the parts differently.

**Download**

- **Windows:** `ampm-viewer-v2.2.1-x64-setup.exe`. Run it to install, or to
  upgrade an earlier version in place (your settings, macros and plots are kept).
- **macOS (Apple silicon):** `ampm-viewer-v2.2.1-arm64.dmg`. Open it and drag
  AMPM Viewer to Applications, replacing the old one.

### Fixed

- **Parts matched by position, not name.** QuantAM keeps its own part names, so
  a build whose `Part(1)` was deleted has a parts CSV running `Part(2)` to
  `Part(16)`, while its .dhxml numbers the same parts `1` to `15`. Before, every
  part got its neighbour's values (and one part none):
  - from **Import from parts CSV**, with DHXML part assignment;
  - from **Add from Excel** of the samples template, with Direct assignment.

  Both now match each part by its X/Y position, with any part assignment, and
  in macros too. The message after an import says "matched by position".

  If you imported parameters or measurements into a build like this with
  2.2.0 or earlier, remove those columns and import them again.

### First start

Neither installer is signed yet. On Windows, if SmartScreen stops the setup,
choose **More info**, then **Run anyway**. On a Mac, the first time: macOS 15
and later, open AMPM Viewer, close the warning, then System Settings > Privacy &
Security > **Open Anyway**; macOS 14 and earlier, Control-click AMPM Viewer in
Applications and choose **Open**.

See `CHANGELOG.md` for the details.
